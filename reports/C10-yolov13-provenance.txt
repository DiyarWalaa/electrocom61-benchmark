   "Lei, Mengqi, Siqi Li, Yihong Wu, Han Hu, You Zhou, Xinhu Zheng, Guiguang Ding, Shaoyi

3. SO THE ANSWER TO "YOLOv13 VERSUS THE OTHER ROWS" IS THAT NOTHING DISTINGUISHES THEM.
   YOLOv13 is not given a provenance the other rows lack, and the other rows are not given
   one YOLOv13 lacks. All eight are cited, none is sourced.

4. iMoonLab IS NEVER MENTIONED. The string does not occur anywhere in the paper. The
   YOLOv13 reference [26] names the authors of the arXiv paper but not the organisation or
   the repository that publishes the implementation.

5. THE ONLY TWO ULTRALYTICS STRINGS IN THE PAPER ARE REFERENCE ENTRIES, both for models
   that are not YOLOv13:
     [20] "Glenn Jocher and Ayush Chaurasia and Jing Qiu, Ultralytics YOLOv8, 2023.
          https://github.com/ultralytics/ultralytics"   -- cited by the YOLOv8s row
     [23] "Glenn Jocher, yolov5, 2020. Documentation at: https://docs.ultralytics.com/"
          -- cited by no row in TABLE I
   Neither is presented as the framework Gaib trained with. The paper's one statement about
   its software stack is in Section IV, PDF p. 3, and names a different thing entirely:
   "The deep learning package tool, Pytorch 2.0.0, is utilised." No Ultralytics version is
   stated anywhere (see C08).

6. THE ONE CODE POINTER GAIB GIVES IS ITS OWN, and it is a notebook rather than a
   repository. Abstract, PDF p. 1: "The source code is available on this link
   www.kaggle.com/code/alielhenidy/e-waste-detection-yolov13". [ELHENIDY]'s abstract gives
   the parallel link "https://www.kaggle.com/code/alielhenidy/yolov12-waste-train". Neither
   link is described as the origin of any of the compared architectures; each is offered as
   the authors' own training code.

7. NOTE ON THE REFERENCE NUMBERING, because it bears on how much weight the [n] labels can
   carry. Gaib's TABLE I row labels are inherited unchanged from Elhenidy's TABLE I,
   including "[12]" on the YOLOv12S row. In BOTH papers, reference [12] is Huang et al.'s
   improved YOLO-V3 paper, and in both papers the YOLOv12 architecture is reference [16]
   (Tian, Ye and Doermann, "YOLOv12: Attention-Centric Real-Time Object Detectors",
   arXiv:2502.12524). The YOLOv12S row therefore cites a YOLOv3 paper in both. This is a
   citation error in the sources; it is recorded because it means the bracketed numbers in
   TABLE I cannot be relied on as provenance even in the weak sense of pointing at the right
   architecture paper.

IMPACT ON THE MANUSCRIPT

No correction required, but this check supplies a fact the manuscript can use and should not
overstate.

The safe formulation is that Gaib identifies every architecture in its table by citation
alone and names no package, repository or version for any of them, YOLOv13 included. It is
NOT safe to say Gaib used the iMoonLab implementation, or the Ultralytics implementation, or
any implementation: the paper's only software statement is "Pytorch 2.0.0", and the two
Ultralytics URLs in it sit inside reference entries for YOLOv8 and YOLOv5, one of which is
not cited by any table row.

Two smaller points, both facts about what is printed:

  - The 648-layer count Gaib gives YOLOv13s is unusually large next to the 214-325 range of
    the other rows apart from YOLOv9s's 930. With no implementation named and no statement
    of whether counts are fused (see C04), there is nothing in the paper that would let a
    reader reproduce or check it. If Section 7.4 discusses published layer counts, this is
    the row with the least behind it.

  - Both papers' TABLE I labels the YOLOv12S row "[12]", and in both papers reference [12]
    is a 2019 YOLO-V3 paper while the actual YOLOv12 reference is [16]. If the manuscript
    cites either table's row labels as evidence of which architecture was evaluated, cite
    the row label text rather than the bracketed number.
